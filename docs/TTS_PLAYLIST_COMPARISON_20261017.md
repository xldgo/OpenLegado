# 朗读蓝牙队列手动对照

入口：设置 → 关于 → 朗读播放对照。仅用于诊断，不改变正式朗读配置。

1. 先正常朗读，使同一章节至少有6段不同段落的音频缓存。打开对照页会复制最近满足
   条件的章节，按段号取最多8段；同段有多个缓存版本时只选最新版本。复制失败即报错，
   不自动换用另一批文件。音频不转码，页面关闭后清除副本，原缓存仍由正常清理规则管理。
2. 连接出现问题的蓝牙设备，保持同一音量、前台与屏幕常亮。先播放A，再播放B；
   不要在两组之间重新准备样本、切换输出设备或更改系统音频设置。每组固定1倍速。
3. 听到卡顿或重播时点击“标记刚才的卡顿或重播”。等本组结束，或手动停止后导出日志。
   A、B分别保存，开始B会清理原始采集记录，但不会覆盖已保存的A日志。可反序B→A复测，
   以排除运行顺序的影响；重跑同组会替换该组结果，请先分享保存。
4. 把A、B日志与听感一起提供：哪组发生、对应第几段、是间隙还是重复段首。需要比较外放时，
   保持本页样本不变，切到外放后重跑并另行保存两份日志。

| 控制项 | A：固定列表 | B：动态追加 |
|---|---|---|
| 文件 | 同一批独立副本、相同顺序和SHA-256 | 同左 |
| 初始装载 | 全部6～8项，一次装载 | 前3项，一次装载 |
| 播放期间 | 应用不追加、不删除 | 换项后按原调度补至前方2项，每次补一项 |
| 历史项 | 保留至本组停止 | 同左 |
| 播放器 | 共用同一实例、插件默认延迟准备 | 同左 |
| 合成与网络 | 不发起；开始前取消并等待正文任务退出 | 同左 |

每轮自动停止正文，等待旧播放器、系统TTS和已取消合成结束，再申请现有音频焦点。
播放结束、离页、进入后台、音频焦点丢失或播放错误都会停止本组，不自动恢复正文。
此对照先限定前台；锁屏连续播放属于另一组条件，不能把前后台两次结果直接比较。

日志包含`comparison.start`的模式、文件顺序和内容摘要，`item_started`、`item_completed`、
`append_begin/end`、`heard_replay`、`finish`事件及原有播放器/原生采样。iOS资源采样增加
匿名输出端口类型、输出延迟、采样率、IO缓冲时长，不采集蓝牙设备名称。正文、书名、
原始文件路径不会写入对照清单；界面的书名/章节仅帮助辨认样本。

A也可能由插件在原生侧维护延迟准备窗口，不能把它理解为“原生完全不变更队列”。
若仅B稳定复现，才进一步缩小到应用追加与其触发的原生维护；若A也复现，需继续查原生
自动换项、文件编码边界及音频路由。两组都正常也不能排除正式长队列、预合成负载或后台
条件相关问题。端口延迟和事件间隔均不是声学录音结果，不能据此确认实际静音时长。

本批只补行为用例源码与格式/差异复核。按用户约定未执行自动测试、分析器、构建或设备
任务；iOS原生采样与真实蓝牙表现需安装后手测，不宣称根因已确认或故障已修复。

## 应用层转换修复后的复验口径

继续使用相同缓存样本、蓝牙输出、音量及前台条件。动态组仍维持前方两项，补充唤醒
改为异步合并，并在执行时读取已确认项目；未调整预合成设置或插件延迟准备参数。

- `index/tag`为采集时插件快照；`confirmedIndex/confirmedTag`为应用已确认归属，
  两者短暂不一致不应再次引发正文回跳、重复起播或提前完成。
- `player.transition_candidate`保留自然转换的前后索引、事件时间和控制归属；
  `player.transition_ignored`记录未通过核对的转换，不能把它解读为音频已经修复。
- `player.item_changed`只记录已提交转换；其中`positionMs:0`表示业务段首归属，
  不表示应用对原生执行了seek。真正的应用定位仍查看`player.seek`。
- 对照组须实际播至最后一段完成。切后台、手动停止或音频焦点丢失导致的截断不能
  用来比较尚未播完的部分；固定组与动态组的索引均从0开始。
- 回调正确与耳机听感分别验收。若已确认索引不回退、无错误完成，但动态追加仍伴随
  原生位置异常或实际卡顿，再进入iOS插件追加路径调查，不直接修改本机Pub缓存。
