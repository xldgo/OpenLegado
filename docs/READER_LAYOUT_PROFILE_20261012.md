# 阅读排版 Profile 基准

本文只保存采样方法与结果；任务状态只维护于 [Active 计划](REFACTORING_ACTIVE_PLAN.md)。应用版本保持 2.0.372+373，基准独立运行，不改用户书架或阅读进度。

## 固定口径

基准入口为 `flutter_legado/tool/reader_layout_profile.dart`，只允许 Profile 模式，调用真实 ParagraphLayoutEngine 和 ReaderTextContent。独立包名为 `io.legado.layout_benchmark`，不初始化数据库或请求书源。Gradle 使用专用 init script 覆写本次包名，正式应用配置不变；Profile 仍执行 Release Rust 原生库及包内摘要校验。

四类固定文本：120 段短章、400 段中英/Unicode 混排长章、超长单段、120 段行内段评。采集端还原夹具并计算 SHA-256；尺寸固定 320×580、首页 530、字号 18、行高 1.6、段距 8、缩进 36、文字缩放 1。中文断行开启，每种文本预热两轮、记录七轮；引擎实例重建、字体引擎缓存保持暖态，不复用完整章节布局。

日志不在计时窗口中导出；先等待夹具输出完成，再采样，采样后等待日志排空。传输按短包拆分，采集端拒绝缺包、缺帧、轮次缺失、版本混杂和错误模式；原始帧记录与每轮值均保存，不只保留平均值。

| 指标 | 含义与限制 |
|---|---|
| `firstPageReadyUs` | 排版开始到首个完整页可用，不包含启动与正文获取 |
| `firstPageFrameSubmittedUs` | 首页可用后由真实渲染器提交框架帧；不是显示器实际呈现时刻 |
| `chapterWallUs` | 包含分批让帧的端到端整章时间 |
| `activeLayoutUs` | 排版处理墙钟时间，排除主动让帧；迁移后包含等待 FFI，不能当作 UI 线程 CPU 时间 |
| `measuredPathUs` | TextPainter 构造/布局和簇盒提取的累计时间；未覆盖所有行度量调用 |
| `unattributedActiveUs` | 排版处理墙钟减已计量测量路径；含分配、规则、适配与 FFI 等，不能直接称为纯算法耗时 |
| 测量次数与页数 | 对照重复测量和布局结果；页数变化先解释规则变化 |
| build/raster/totalSpan | 保存真实 FrameTiming；分项汇总不等于整个样本期间没有阻塞 |
| 帧间隔与长间隔数 | 持续 Ticker 捕获构建回调之外的 UI 阻塞；长间隔阈值为刷新预算 1.5 倍，不等同于准确丢帧数 |
| RSS | 进程常驻内存与批次边界采样峰值；包含引擎/native，不是 Dart 堆或瞬时峰值 |
| FFI | Dart 基线为 null；Rust 样本记录编码、排队/调用、服务内计算与解码；调用时间包含 Rust 工作，不能相加 |

每轮保留原始时间，汇总使用 nearest-rank P50/P95；帧原始数据可再次汇总。七次采样的 P95 接近最大值，需结合原始分布判断。Flutter 官方建议性能结论使用物理设备的 Profile 模式；模拟器只用于同环境的相对比较，见 [Flutter 性能测量](https://docs.flutter.dev/perf/ui-performance) 与 [FrameTiming 回调](https://api.flutter.dev/flutter/scheduler/SchedulerBinding/addTimingsCallback.html)。

## Windows 复测命令

在仓库根目录使用匹配的 Release 原生库：

```powershell
python scripts/dev.py build ffi android --profile release --abis x86_64
```

进入 `flutter_legado/android`，使用当前 Java 17 与 Flutter SDK PATH，构建独立 Profile 包：

```powershell
$profileDefines = @(
    'LAYOUT_PROFILE_LABEL=dart-baseline',
    'LAYOUT_PROFILE_REVISION=<实际提交或带采样改动的基线标识>'
) | ForEach-Object {
    [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($_))
}
./gradlew.bat :app:assembleProfile --init-script ../tool/reader_profile.init.gradle `
    -Ptarget-platform=android-x64 -Ptarget=tool/reader_layout_profile.dart `
    "-Pdart-defines=$($profileDefines -join ',')"
```

回仓库根目录，明确填入本次实时探测到的设备与 ADB 路径。真机使用对应 ABI / Flutter target；同组前后测试保持设备、ABI、SDK 和字体一致。

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$adbPath = '<本机 platform-tools/adb.exe>'
$deviceId = '<本次实时确认在线的设备>'
$apkPath = 'flutter_legado/build/app/outputs/apk/profile/app-profile.apk'
python scripts/dev.py verify apk android --profile release --abis x86_64 --apk $apkPath
& $adbPath -s $deviceId install -r $apkPath
python scripts/reader_layout_profile.py --device $deviceId --adb $adbPath `
    --log flutter_legado/build/reader-layout-audit/profile/before.log `
    --output flutter_legado/build/reader-layout-audit/profile/before.json
```

采集脚本只重启独立基准包，不清空设备全局日志，不构建、安装或触发 CI。已有日志可省略 `--device` 离线复算。更换 Rust 核心后使用 `rust-after` 标签及 `after.log/json`，并添加 `--baseline flutter_legado/build/reader-layout-audit/profile/before.json`；工具拒绝环境、配置或正文不一致的比较，并拒绝覆盖基线。SDK、ABI、字体及宿主环境仍需对照归档清单。归档基线 APK、工具链、源码/基准入口摘要和完整日志。

本入口测量首个正文页及分批排版，不包含数据库/网络、整应用启动、快速翻页动画、完整布局缓存命中或 iOS GPU 行为。那些场景在最终应用中另做 Profile 回归，不以本入口数据替代。

## 迁移前采样结果

下表为每轮指标的 P50，单位 ms。整章墙钟时间包含分批让帧，与活跃计算时间不同。

| 文本 | UTF-16 长度 | 首个完整页可用 | 首页框架提交 | 整章墙钟 | 活跃计算 | 已计量文字测量 |
|---|---:|---:|---:|---:|---:|---:|
| 短章 | 6635 | 7.455 | 17.547 | 252.574 | 121.776 | 108.582 |
| 中英混排长章 | 81783 | 9.365 | 17.020 | 1085.581 | 566.439 | 496.193 |
| 超长单段 | 10500 | 37.096 | 49.900 | 49.901 | 37.049 | 30.237 |
| 行内段评 | 8075 | 8.511 | 17.404 | 285.601 | 150.282 | 133.134 |

按各轮比值的中位数，已记录文字测量路径约占活跃计算的 81.7%–89.0%；这说明不能把全部活跃时间当成可直接迁往 Rust 的纯算法成本。超长单段帧间隔最大值的七轮中位数为 48.239 ms，仍反映段落级分批无法中断单次长段计算。本节只记录迁移前样本，迁移后同口径结果见下节。

迁移还会将现有规则修正为上游语义，因此前后结果用于评估完整改造的收益，不能把差值全部归因于语言。页数、行数或测量次数变化需要解释；Rust 纯计算与 FFI 分项单独记录，不为比较额外保留生产环境旧引擎。物理设备复测时保持宿主与设备负载稳定，并重新核对 SDK、ABI、字体和窗口 DPR。

原始日志、28 轮结果、帧数据、构建清单与基线 APK 保存在忽略目录 `flutter_legado/build/reader-layout-audit/profile/`，分别为 `before.log`、`before.json`、`before-build-manifest.json`、`before-native-meta.json` 与 `reader-layout-before.apk`。采样结束后已移除独立测试包，恢复并验证原 Debug native 库；原阅读器包与数据保持原状。方法与摘要在本文可追溯，原始诊断文件不纳入 Git。

## Rust 迁移后的同环境结果

最终比较使用 `before.json` 与 `after-view.json`：同一 MuMu 实例、Android x86_64、Flutter 3.47.7、DPR=1、60 Hz，正文摘要及全部排版配置经采集脚本核对相同；两侧各四类、七轮有效样本。当前代码为 `6c3b04da2` 加工作区 Rust 迁移，不是另一个已提交版本。相同工具链的归档 APK分别为 `reader-layout-before.apk` 与 `reader-layout-after-view.apk`。

重装后曾出现 DPR=3 的窗口，`before-final.json` 与 DPR=1 的新样本比较被工具拒绝。这组记录及最初未优化的新实现只用于诊断，不纳入下表；不通过修改环境记录强行比较。

短章、混排长章和段评整章时间下降，超长单段仍回退；混排与段评首个完整页也未全面加快。上游需要内容块前瞻，并延迟一页输出，不能把旧首屏行为强套给新会话。首批上限提高到 16 段，后续为 8 段，文字测量仍保留 8 ms 预算；不是一次同步测量整章。有限宽塑形、共享样式、结构字段、无损数组传输和 Dart 只读字形视图针对实际测出的成本，没有改变断行/分页规则。

## 共享存储与页面所有权优化后的结果

2026-10-12 用户授权架构优化。本次对照使用迁移后、优化前的 `after-view.json` 与
`after-architecture.json`，两侧均为 MuMu Android x86_64、Flutter 3.47.7、DPR=1、60 Hz，
正文、配置、页数与测量次数一致。四类各七轮，共28轮有效样本；只使用完整 Profile 数据，
不把当前优化前后差值归因于单一改动。

本轮改动：Rust 定稿页转移所有权并释放历史页面；输出共享文字/样式及小端 f32/u32
缓冲，不新增输出格式标识或旧格式解析；Flutter 通用元素、行文字及选区字形共享底层数据，
不保留逐字几何副本；会话页面视图不再逐批复制引用。缓存另增加16 MiB估算预算，
相邻章串行预排。该基准不覆盖缓存命中及相邻章预排，不能把下表收益归因于缓存策略。
