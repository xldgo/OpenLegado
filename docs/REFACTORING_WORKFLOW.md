> 生效日期：2026-09-27
> 本文规定重构任务如何进入、派发、实施、验证和关闭。当前任务与进度只登记在 [REFACTORING_ACTIVE_PLAN.md](REFACTORING_ACTIVE_PLAN.md)。

## 2. 重构目标和差异裁决

1. 第一阶段完成书籍阅读闭环：搜索、书架、加书/开书、详情、目录、正文、翻章、换源、离线缓存、进度保存与恢复。
2. 书籍主流程后推进其他现有功能；媒体顺序为漫画/视频，然后音频。具体开放项仍须进入 Active 计划并按证据排序。
3. 上游用于功能、交互语义及用户结果核对；UI目标由设计系统维护。Rust + Flutter保持当前实现架构，不为复刻上游内部结构而整体改架构。
4. 若参考版与 Android 原版或用户已确认规则在功能行为上实质冲突，暂停相关任务并向用户提交差异、复现/截图证据、影响范围和推荐选项。不得自行选择；其他互不依赖的工作可以继续。
5. 本项目为重构项目，**未经允许禁止新增 Android 原版不存在的功能**（用户明确授权的除外，如 LargeTitle 大标题、颜文字空态彩蛋、阅读热力图、AI 摘要改写/角色卡 Characters/相关书 RelatedBooks（2026-09-05 授权，记录正本见 [历史授权计划](过期文档/UI_ONE_TO_ONE_CLONE_PLAN_20260905.md) §〇）等，授权记录见提交与文档）；发现未授权的偏离项（如推荐算法等）必须清理，一切以不偏离重构核心为目标（2026-08-29 用户修订授权口径）。不删除Android原版双轨代码，不隐式实施不可逆数据库迁移。
6. 不以“零 TODO/桩”“全部完成”或百分比作为完成依据。完成状态须限定范围、HEAD/提交、测试或验收证据。

## 3. 状态定义和任务记录

每个任务在 Active 计划中只能有一个当前状态：

| 状态 | 使用条件 |
|---|---|
| 待核验 | 仅有历史登记或推测，尚未证明当前 HEAD 存在问题 |
| 已确认待修 | 当前实现可复现失败，需求与验收已明确 |
| 实施中 | Agent 已接单且工作范围、分支/文件边界清楚 |
| 待复验 | 代码已完成，所需 CI、设备、截图或评审证据尚未齐全 |
| 待用户素材 | 工程路径可继续，但真实验收缺账号、样例或硬件 |
| 待用户裁决 | 参考版、原版或既有规则冲突，或涉及未确认取舍 |
| 已关闭 | 代码/文档落点与必要验证证据齐全，验收范围已经写清 |
| N/A | 经核查确定不适用，并记录理由和证据 |

每条登记包含：唯一编号、优先级及用户影响、目标行为、当前实现路径、原版/参考版来源、复现或截图证据、依赖和非目标、执行 Agent、验收条件、验证命令/测试、提交号和剩余限制。专题报告可详细描述证据，但不能另维护一个与 Active 冲突的“当前状态”。

## 4. Agent 分工和任务派发

没有用户明确要求时不使用子代理，由当前Agent执行和复核。以下分工与审查派发要求仅在用户授权多代理时适用；不因职责表或高风险分类自行启用子代理。

- 主Agent只负责任务拆分、派发、跟进、diff复核、验收、文档与提交；编码、取证、构建和设备验证交给子代理。
- 子代理失败、超时或卡住时，先说明情况并取得用户同意，才可由主Agent接手；不擅自兜底。
- 任意时刻最多两个子代理并行。先判断任务是否可自包含且隔离有价值，符合条件时派发。

- **Agent 路由表**（按任务能力选择执行者；名称是项目职责标签，不绑定特定 Agent 产品的配置名）：

  | 触发条件 | 执行职责 | 执行侧 | 证据形态 |
  |---|---|---|---|
  | 代码实现/修改 | 编码 Agent | 按项目授权环境 | 提交 + 自测输出 |
  | `flutter_legado/**`、`rust/**` 的常规验证 | 不额外派发；以 CI 为准 | CI | CI 运行结果 |
  | 需实机验证 | QA Agent | 经实时探测可用的测试设备 | 脚本退出码 + 日志/截图 |
  | UI 布局/交互改动 | UI 验收 Agent | 经实时探测可用的设备 | 同条件截图与差异记录 |
  | 跨模块 / FFI 契约 / 公共 API 变更，或大范围重构 | 独立审查 Agent | 仅提供最小必要上下文 | 提交前审查结论 |
  | 有 bug 且 CI/本地复现不出根因 | 调试 Agent | 仅提供最小复现和错误信息 | 根因结论 + 最小复现 |
  | 引入新依赖 / 技术选型 / 大范围调研与依赖梳理 | 研究 Agent | 按任务需要选择 | 调研结论 + 出处 |

  - Agent 名称、产品类型和可用工具以当前执行环境为准；本表仅定义职责和证据，不维护特定产品内置角色清单。
  - 需要云端/外部审查时只发送最小 diff 或最小复现与错误栈，不发送无关源码。
  - 常规任务先判断能否派发（可自包含、上下文隔离有价值、可并行），能派则派
- **冲突避让**：多个子代理同时改代码时必须避让同一文件/模块；任务分配须满足文件不重叠、工作量平均、技能匹配三项原则

## 5. 单个任务的执行门

### 门 A：立项和复核

1. 从 Active 计划选取任务，确认编号未重叠、状态未过时、修改路径无未提交用户工作。
2. 查当前源码、调用路径、现有测试、关闭提交和历史审计；先排除已修、误报或 N/A。
3. 记录实际用户影响并按主流程阻断、主流程严重干扰、一般功能/视觉差异、低优先级维护排序。
4. 写清成功条件、失败条件、范围边界、回滚点和所需证据。条件不明确时不派实施任务。

### 门 B：复现和设计

1. 逻辑问题先按开发规范确定必要回归；UI问题先复现具体操作与可见影响，按需留存截图或录屏；性能问题先分段计时。
2. 用固定 JSON/HTML/JS 样本和 localhost loopback 测网络、书源与异步边界，避免必需测试依赖真实网站。
3. DB 工作先检查 schema、旧库兼容、事务边界、迁移幂等、备份和失败恢复。
4. 若涉及 FFI、公共 API、跨模块或不可逆改动，先冻结契约/方案并触发提交前评审。
5. 参考版与 Android 原版或明确规则有实质冲突时进入“待用户裁决”，不进入实施门。

### 门 C：实施

1. Agent 只修改任务卡授权路径；额外发现另建任务，不顺手扩散修改。
2. 一批围绕一个根因或紧密关联行为；不把视觉、解析、DB schema 和依赖升级混成单批。
3. Flutter UI 任务可先用 Mock 开发交互；Mock 通过不证明真实 FFI、DB 或书源正确。
4. FFI 变更顺序固定为：更新 `API_CONTRACT.md` → BookApi/RustApi/Mock → Rust 实现 → 同一次 FRB codegen 生成 Dart/Rust → 重编相应 native library → hash/契约核对 → 双端验证。禁止手改生成文件。
5. DB 变更必须提供旧库升级、重复打开、迁移中断/恢复和关键数据保留证据；不可逆项明确标出并先评审。

### 门 D：验证与实机

1. 本地范围和测试有效性统一遵循 [DEVELOPMENT_CONVENTIONS.md](DEVELOPMENT_CONVENTIONS.md)「自动化测试与有效性规范」，不默认运行全量或无关平台构建；常规全量门禁交由既有CI。
2. `flutter_legado/**`、`rust/**` 的常规分析和测试以 CI 结果为准；不重复派角色跑同一验证。
3. 只在 CI 覆盖不到的 UI 交互、生命周期、平台差异和真源验收上执行设备测试。
4. 每次设备任务按下述设备说明实时探测实例、ADB端点、网络、尺寸、目标包和变体，不假设历史端口可用。修复先在官方测试档验证，再按用户要求安装至验收档；MuMu快捷安装不代替专项交互/播放验收。
5. UI验收遵循设计系统「当前UI目标与验收」，围绕本次可用性与交互结果取证；涉及原生平台的效果不能仅凭Widget测试宣称实机通过。
6. 任何失败都记录原始失败、复现条件和处理结果；不得把一次偶发通过或 Agent 自述当作独立证据。
7. **证据有效性**：Agent自述不能代替独立证据。测试质量规则见通用开发规范，不在此复述。
8. **平台验证边界**：Android结果不能直接关闭iOS专属的权限、后台、WebView、音频、通知和签名问题；共享源码不代表平台运行行为一致。
9. **iOS 验证边界（2026-09-27）**：只允许记录 CI 编译检查或 iOS 模拟器运行结果，记作「**iOS 编译/模拟器验证**」；iOS 真机相关项在缺少设备（本地 Mac / Apple 设备 / 可授权测试者）期间一律保持「**待外部测试能力**」状态，不安排 Agent 自行 iOS 真机验收；iOS 签名不作为当前主流程完成条件。恢复真机测试的预留入口（签名脚手架与文档）见 Active 计划 P2-26。

### 设备验证说明

- **模拟器验证档（官方 Android SDK 模拟器 `Legado_API_36`）**：
  - **AVD 与系统镜像**：`Legado_API_36`，使用 `system-images/android-36/google_apis/x86_64`（Android 16 / API 36，userdebug 构建）；持久配置 `1080×1920`、`480 dpi`（逻辑尺寸 `360×640 dp`，与 `docs/parity_shots/` 历史基准对齐，无需每次 `wm` 覆盖）；ABI 支持 `x86_64,arm64-v8a`（含内置 `ndk_translation`）。
  - **工具与启停（使用新版 Android CLI，弃用 `sdkmanager`）**：
    - `android.exe`：`$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest\bin\android.exe`
    - `adb.exe`：`$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe`
    - 启动：`& $android emulator start Legado_API_36`（阻塞至完全启动就绪后返回）；停止：`& $android emulator stop Legado_API_36`。
  - **设备号探测与能力**：每次执行前必须先用 `adb devices -l` 探测在线实例，认准 `model:sdk_gphone64_x86_64`（`device:emu64xa`）对应的 `<serial>`（如 `emulator-5554` 或 `emulator-5556`），所有 `adb` 命令显式加 `-s <serial>`。原生支持 `adb -s <serial> root`、标准单屏 `exec-out screencap -p`、`uiautomator dump`、剪贴板与输入法；我方应用语义文本在 **`content-desc`**（Flutter 语义树），不在 `text` 属性；模拟器内访问宿主机 `127.0.0.1` 用 **`10.0.2.2`**（SLIRP 网络不支持 ICMP `ping`，联网检查请用 TCP/HTTP）。
  - **冒烟脚本**（构建+安装+启动+崩溃检查）：`.\scripts\emulator_smoke_test.ps1 -Device <serial>`（可加 `-CheckUI` 做书架主界面元素检查；复用 APK 加 `-SkipBuild`）；退出码 0=通过 1=失败。
  - **端点时效性（每次派单前必读）**：本节及历史文档所载设备号/端口均随实例运行状态变化；每次设备任务前必须以 `adb devices -l` 与 `android.exe emulator list` 实时探测为准，**不得假设固定端口恒可用**。历史模拟器归档见 `docs/过期文档/MUMU_EMULATOR_NOTES_ARCHIVE_20261013.md`。

MuMu快捷安装与自动连接参数见 [README的构建说明](../README.md#编译与测试)。

### 门 E：验收、提交与关闭

1. 主 Agent 确认 diff 未越界、测试对应当前改动、截图/日志来自正确设备与版本、结果符合验收条件。
2. 高风险改动确认有 `code-reviewer` 结论后方可提交；一般小修不强制评审。
3. 按项目 Conventional Commit 规范提交；代码批次按规则同步版本、CHANGELOG 和应用内更新日志。文档批次按文档署名与日期规则办理。
4. 关闭 Active 项时记录提交/CI/测试/QA/截图证据及限制。工程完成但外部素材缺失时，只关闭工程部分，验收仍为待素材。
5. 阶段结束核对 Active、专题证据、docs 索引与 Git 状态；下一阶段只从 Active 开放队列启动。

## 6. 总体阶段与进入/退出条件

不设置固定日历周。每一阶段必须通过退出条件才转下一阶段；可并行的只限已拆分且不共享文件、契约或设备的工作。

| 阶段 | 顺序和工作范围 | 退出条件 |
|---|---|---|
| **0 进度校准** | 核对Active、当前缺陷、设计系统、剩余风险和HEAD；先处理重复、过时和相互矛盾状态，不从历史视觉台账派发任务。 | 当前任务有唯一编号与状态；历史数字不再冒充当前结论；需复验/裁决/素材的项已分开登记。 |
| **1A 搜索和书架** | 搜索流、分页、取消、空态/失败；加书、书架刷新/分组/排序、书架开书。 | 搜索与书架状态一致；旧请求不覆盖新状态；关键空/错/有数据形态有测试。 |
| **1B 目录和换源** | 目录本地/网络加载、刷新、章节定位、分页、换源成功/失败/取消。 | DB 与 UI 的书籍键、目录、进度和派生字段一致；取消不提交半成品。 |
| **1C 正文和进度** | 正文缓存、翻章、快速连续操作、后台保存、退出与重进恢复、清缓存。 | 章节内容/进度一致；数据写入和恢复可重复验证；设备复验项有证据或显式阻塞。 |
| **2 书籍周边能力** | 与书籍链路直接相关的书源管理、规则解析、QuickJS、网络行为，按真实命中及可复现性逐项推进。 | 每个兼容能力有来源语义、fixture、回归结果和明确的平台边界；不追求机械模拟完整 JVM。 |
| **3 其他现有功能和界面** | RSS、设置、备份、Web等既有能力；按当前任务检查适用主题、布局与交互。 | 功能和界面结果符合已确认需求，必要设备验收及未测范围有记录。 |
| **4 漫画/视频** | 在样例可用时验证加载、呈现、翻页/播放、缩放/全屏、错误与退出。 | 自动测试和真实样例验收分开通过；素材缺失保留待验收。 |
| **5 音频** | 播放、章节切换、进度、后台续播、焦点与媒体键。 | 音源和适用设备完成端到端验收；模拟器无法证明的硬件项不能销账。 |
| **6 阶段收口** | 整理提交、CI、截图、外部验收及遗留风险，重排下一阶段开放项。 | Active、Git、CI/QA 与专题证据一致；所有未完成项有负责人、阻塞和下一步。 |

### 阶段 1 主流程验收矩阵

| 子流程 | 必测状态/交错 | 数据验收 |
|---|---|---|
| 搜索 | 正常流式、分页、无结果、网络失败、取消、再次搜索、跨源重复 | 结果状态和去重范围与已确认语义一致，旧会话不污染新会话 |
| 书架 | 空/有书、加书、移除、刷新、分组/排序、从书架开书 | 加入记录、书籍 URL、来源和 UI 列表一致，无重复/幽灵项 |
| 目录 | 本地命中、网络抓取、空目录、失败、刷新、重定向、相对分页 | 章节 URL 和顺序正确，刷新不丢阅读位置，缓存清理符合已确认语义 |
| 正文/翻章 | 正文缓存/未缓存、上下章、快速连翻、失败后重试、章节边界 | 当前章节、正文、下一章预览和阅读进度始终属于同一本书/当前请求 |
| 换源 | 预拉命中/未命中、抓取失败、用户取消、重复点击、换源后续读 | 事务前失败/取消不污染 DB；完成后目录、来源、章节和进度映射一致 |
| 保存/恢复 | 阅读中保存、切后台、退出、重启/重进 | DB 中进度与书架展示、重进章节和阅读位置一致 |

## 7. 跨轨、DB、视觉和素材专项流程

### FFI/API

只有现有接口无法满足已确认需求时新增 API。契约先写清方法、输入/输出、错误语义、Mock 形状与兼容策略；双轨评审后实现。codegen 产物和 native library 必须成套更新，确认 Dart/Rust hash 一致后再进行真实 FFI 验证。

### 数据库/缓存

记录旧数据来源和受影响字段 → 准备旧 schema fixture → 设计事务/迁移 → 覆盖新装和升级 → 注入迁移/写入失败 → 核对备份恢复与关键行 → 评审不可逆风险。缓存清理同时核对 DB、内存状态和重新开书行为。

### UI设计与交互验收

按 [设计系统的当前验收口径](design_system.md#当前ui目标与验收2026-10-24) 确定本次用户行为与可见结果 → 修改 → 定向复验 → 将证据与未测范围回填Active。历史像素比对规范和台账不再是任务入口。

### 书源/规则与网络

基于真实源候选选择单一能力 → 固定输入响应 → 对照 Android 对应实现/已确认语义 → 单点修改 → 运行 parser/QuickJS/网络 fixture → 统计受影响源和未覆盖行为。网络测试走本地 loopback；真网站只用于可选外部验收。

### 外部素材

包括 WebDAV 账号、可用音频源、漫画/视频样例、触发段评/验证码/倒计时/外链的书源、皮肤 ZIP、真机媒体键，以及可选的脱敏书架 JSON。按对应阶段插入验收；素材未到时继续离线验证，真实环境项保持“待用户素材”。不保存或写入真实账号凭据到仓库文档。

## 8. 验收证据格式

每次 Agent 交付按以下格式回报：

```text
任务编号 / HEAD / 分支：
根因或实现目标：
修改文件：
测试命令与结果（含退出码）：
CI 链接或运行 ID：
设备/包/变体（如适用）：
截图、日志、DB/fixture 证据路径：
提交号：
未完成范围与阻塞：
```

关闭报告必须区分“代码已交付”“CI 已通过”“设备/素材已验收”。缺一项就保留对应待办状态，不允许把三个状态混写成一个“完成”。
