# 备份与恢复完善计划

任务：BACKUP-RESTORE-20261024；起始基线：dev / a4f0cb1d6。
参考本地原版363540972与HapeLee c4182eb9b，不代表远端最新。

## 目标与边界

让本项目已有业务能够完整备份、恢复结果可信，本地和WebDAV使用同一份备份包，
敏感内容有明确的导出授权及加密方式。采用现有Rust业务服务、Dart窄接口和设置仓储，
不照搬Android存储实现，不扩展其他业务功能，不提升应用版本。

原版与HapeLee有不同的数据类型和设置，按项目实际实体核对，不承诺照收未知字段。
不备份音频/章节/HTTP/封面等可重建缓存；用户选定的背景、字体等原始资源另行清点，
不能把路径字符串备份成功视作文件已备份。旧偏好键按开发规范处理，不新增迁移。

## 顺序与交付

| 批次 | 实施内容 | 验收与依赖 |
|---|---|---|
| B1 恢复可信性 | 保留现有六类数据及FRB DTO；Dart返回恢复统计；Rust先校验文档与实体，再以单事务恢复，失败不跳过条目；版本/格式错误准确返回；ZIP未实现前移除文件选择器的ZIP声明并明确拒绝 | 实际数据库中后段解析/写入失败均不留下前段修改；正确文件返回准确计数；失败不应用偏好，偏好失败单独报告。业务事务与Preferences不冒称跨存储原子 |
| B2 完整业务快照 | 清点当前持久化实体，补齐分组、标注/高亮、RSS收藏/已读、规则订阅/词典/TXT目录规则/自动任务、HTTP及云TTS配置/手选音色、阅读记录明细/会话；确认Rust config与Flutter偏好归属；按依赖顺序恢复并保留实体ID | 逐域复用已有仓储；以混合业务快照验证新库恢复、覆盖更新和重复恢复，保持引用关系；不为每个字段机械新增用例。变更格式/DTO时先更新契约并成套生成/重建 |
| B3 统一备份包与传输 | 以版本化清单+分域JSON形成ZIP；本地创建与WebDAV上传同一包，云端列表选择后下载再走同一恢复入口；导出文件用临时文件完成后替换；核对上游ZIP文件名与字段映射，明确支持项和不支持项 | 本地/云端同一夹具恢复结果一致；缺文件、损坏ZIP、非法路径及未知版本明确失败；恢复不调用上传、不覆盖远端；不把现有两个JSON同步继续称为完整备份 |
| B4 本地密码与敏感内容 | 密码入口移到备份页，使用凭据接口保存；Rust负责敏感区加解密，格式记录算法/参数；本项目新格式采用带认证加密，上游AES只作为明确的导入适配；WebDAV密码、服务器配置及可选云TTS凭据列出敏感清单，不默认明文导出 | 密码错误/缺失/密文损坏在写入前失败；密码不进入备份或日志；未选择导出云凭据时只保留引擎配置并提示需重新配置；上游解密语义使用固定样例核对 |
| B5 策略与自动化 | 实现仅保留最新、设备命名、自动备份间隔和新备份检查；复用现有应用生命周期及任务边界，不自建第二套调度框架；自动备份须调用真实B3流程 | 新包成功后才删除旧包/更新时间；上传失败保留可用本地备份；自动与手动避免互相覆盖。Android/iOS后台执行能力分别声明，不承诺系统未允许的定时唤醒 |

B2先完成清单和已有仓储能力核对，缺失的业务写入接口单独冻结后补齐，不能直接复制数据库文件。
B3接线上游包时对两份上游差异逐项明确，不把缺失数据默认为“恢复完成”。
B4完成前现有JSON仍属未加密格式；B1不声称已解决凭据导出问题。

## B2的数据清单与顺序

| 归属 | 要核对并纳入的内容 | 恢复顺序与边界 |
|---|---|---|
| 书架 | 书籍、分组、书签、标注/高亮及其规则 | 先分组/书籍再关联数据；保留实体ID，不能把分组位标识恢复到不存在的分组 |
| 源与规则 | 书源、RSS源/收藏/已读、订阅、替换规则、词典、TXT目录规则、键盘辅助、自动任务、搜索历史 | 复用正式仓储；定义同ID覆盖语义，避免重复恢复不断新增；搜索结果临时表不纳入 |
| 朗读 | HTTP TTS、云引擎、已选择的音色及源音色目录 | 先引擎后音色，设备系统语音的可用性需重新核对；实际密钥由B4凭据策略处理，不通过普通业务JSON导出 |
| 阅读统计 | 累计记录、明细、会话及其派生统计归属 | 原始记录优先；避免把派生合计与原始明细恢复后重复累计 |
| 设置与文件 | Rust config、Flutter普通偏好、阅读样式、用户背景/字体 | 明确唯一权威数据，逐项剔除运行时状态/路径缓存/凭据；本地文件须实际打包并重定位，不能只恢复原机器路径 |
| 登录及敏感数据 | WebDAV连接密码、Cookie与书源运行时变量的导出范围 | 在B4冻结敏感清单与显式选择之前不扩大导出；隐私密码摘要、本地备份密码及设备密钥不打包 |

当前已有上述多类Repository，但不能据此假定全字段导入和保留ID的写入均可直接使用；
B2实施时先核对实际SELECT/写入能力、实体引用和重复恢复行为，再冻结格式与统计扩展。
